# Phase 3 development protocol

The baseline is the accepted Phase 2 commit `bf8a6162b0b2dbd129be591e7134b0563008e778`. The fixture contains original public development material. Run both arms from clean archives with the same frozen 2 GB model, seed 71, one model thread, a 2 GiB cgroup limit, zero swap and loopback only. Each run has fresh workspaces and a disposable memory database. Isolated memory writes are necessary to observe what an owner would later retrieve.

* **Real-model documents.** Create a one-page PDF for each row and run the normal document workflow. Award one point per answerable row for the correct fact, verified against its source and retrievable as a verified note. On the missing-answer row, require abstention and no verified finding. Report correct content, false confirmations and lost coverage separately.
* **Controlled document challenges.** Feed each of the seven correct claims and all eight wrong claims with the genuine page citation through the document workflow. A correct claim must pass and yield its note. A wrong claim must fail confirmation and stay out of verified memory. The page contains realistic distractors, including another entity with the same number and reciprocal subject/object roles. Score each of the 15 cases independently.
* **Existing memory.** Open a database in the old format with all 15 document claims already marked verified and with their original pages available. Also include an unverifiable document note with its source unavailable and an unrelated verified fix. Check the ordinary search path after two opens. Good and unrelated records should survive. Bad and unsupported notes should disappear from normal recall. Preserve the records for inspection. Score all 17 records.
* **Calculator.** Run the three fresh questions with the real model. Score the delivered final value and record whether Python actually ran. Separately replay the seven specified drafts and reviews, executing their Python with bubblewrap. A successful calculation must return its complete result even if a model proposes a different one. Failed or empty computations must not deliver an invented value. The no-code control allows model revision.
* **Delayed owner.** Use the paired phone API with the real model. Poll an unanswered job for at least 15 seconds, terminate its server process, start a new one on the same saved home and poll for at least another 15 seconds. Submit the reply only then. Require the same job and prompt IDs, no interim answer or consumed attempt, the original pairing, and a final area of 44. Record observed delays and process IDs.

Report the scores separately for natural model behavior and controlled failures. Publish the raw records, elapsed time and peak cgroup memory. Keep all completed attempts and label reruns.
